# i18n — how Petra speaks Hebrew and English

Master plan: `docs/us-expansion-plan.md`. Progress: `docs/us-expansion/PROGRESS.md`. Decisions: `docs/us-expansion/DECISIONS.md`.

## How it works
- **The business decides the language.** `Business.locale` (`he-IL` | `en-US`, + `country`, `currency`, `timezone`) → `src/lib/locale.ts` (`LOCALE_CONFIG`: lang, dir, hourCycle, date-fns locale).
- Rendering: `src/i18n/request.ts` (next-intl "without i18n routing") → `resolveRequestLocale()` (`src/i18n/resolve-locale.ts`): session business → its locale; no business (public pages) → `NEXT_LOCALE` cookie → `he-IL`. A cookie can never override a business.
- `src/app/layout.tsx` sets `<html lang dir>`, the font (`--font-sans` = Heebo / Inter) and `NextIntlClientProvider` (messages + business timezone).
- Messages: `messages/he.json` (source of truth for Hebrew), `messages/en.json` (American English). Namespaces per feature (`common`, `nav`, `tasks`, `customers`, …). A key missing in en.json falls back to Hebrew at runtime, but `check:i18n` fails on it.

## Using it
```tsx
"use client";
import { useTranslations } from "next-intl";
import { useBusinessLocale } from "@/hooks/useBusinessLocale";
import { formatCurrency, formatDate, formatTime, dateFnsLocaleFor, currencySymbol } from "@/lib/format";

const t = useTranslations("tasks");
const tc = useTranslations("common");
const { locale, currency, timezone } = useBusinessLocale();
t("toolbar.newTask");                         // plain
t("list.count", { count: 3 });                // ICU plural / {vars}
t.rich("help.body", { b: (c) => <b>{c}</b> }); // inline markup
formatCurrency(150, { locale, currency });    // "‏150 ₪" / "$150.00"
format(d, t.raw("dateFormats.short"), { locale: dateFnsLocaleFor(locale) });
```
Server components / route handlers: `const t = await getTranslations("ns")` (from `next-intl/server`). API routes are Phase 2 — they will read the locale from the session business, never from the request.

## Migrating a file (Phase 1 recipe — one file per agent)
1. `node scripts/extract-hebrew.mjs <file>` → every Hebrew string with its line. **Copy** strings into the fragment, never retype.
2. Write the agent fragment `{ "he": { ns: {…} }, "en": { ns: {…} } }` (the lead merges with `npm run i18n:merge -- <fragments>`; agents never edit `messages/*.json`).
3. Replace each string with `t("…")`. Rules:
   - **Hebrew is verbatim** — same characters, punctuation, spaces, emoji, geresh (׳/'), dashes. No rewording, no "fixes". Rendered output for a Hebrew business must be byte-identical.
   - Interpolation → ICU `{name}`; keep surrounding text identical (`` `נמצאו ${n} משימות` `` → `"נמצאו {n} משימות"`). Only convert a ternary to an ICU `plural`/`select` when every branch renders exactly as before; otherwise keep two keys.
   - ICU escaping: `{` `}` must be written `'{'` `'}'`; `''` is a literal apostrophe only before `{ } # |`; a Hebrew `'` (צ'אט) needs no escaping. No `<tag>` in plain `t()` messages (use `t.rich`).
   - Module-level constants with labels (`const TABS = [{ id, label: "…" }]`): keep the ids/logic, move only the label (e.g. `labelKey: "tabs.all"` + `t(tab.labelKey)`, or build inside the component). Never change ids, enum values, query params, API payloads.
   - **Hebrew that is DATA, not UI** (compared with DB values, sent to the API, matched by regex on user input, Meta template params, CSV import column names) stays and gets `// i18n-ok` on the same line + a note in the agent report. Phase 3 handles it.
   - Labels imported from `src/lib/*` (`getStatusLabel`, `SERVICE_DOG_PHASES`, `LEAD_SOURCES`…) are Phase 2/3 — leave the import.
   - Hebrew comments may stay (the checker ignores comments).
   - No hardcoded `"he-IL"`, `"ILS"`, `"Asia/Jerusalem"`, `₪`, `from "date-fns/locale"` in a migrated file: use `useBusinessLocale()` + `src/lib/format.ts` (`currencySymbol()` keeps a "₪{n}" layout identical). `utils.formatCurrency/formatDate` calls → `format.ts` with the business locale (identical output for he-IL).
   - date-fns patterns live in messages and are read with `t.raw(...)` (Hebrew pattern verbatim; English = US order `MM/dd/yyyy`, `h:mm a`).
4. RTL → logical CSS: `node scripts/codemod-logical-css.mjs --write <file>`. The mapping is **mirrored** (D-003): Petra was built RTL, so `ml-`→`me-`, `mr-`→`ms-`, `left-`→`end-`, `right-`→`start-`, `text-left`→`text-end`… Hebrew stays pixel-identical, English becomes the mirror image. Then by hand:
   - directional icons (`ChevronLeft/Right`, `ArrowLeft/Right`, "back"/"next"): add `ltr:-scale-x-100` (or `<DirIcon icon={…}>`). Never `rtl:` (that would change Hebrew).
   - `translate-x-*` slide-ins, `bg-gradient-to-l/r`, inline `style={{ left/right/marginLeft… }}`: keep Hebrew as is and add the `ltr:` mirror (`translate-x-full ltr:-translate-x-full`) when the English layout would be wrong.
   - true exceptions (phone numbers, code, numbers inside `dir="ltr"`): leave and mark `// rtl-ok`.
5. Add the file to `scripts/i18n-migrated.txt`, then:
   ```bash
   npm run check:i18n                                    # no Hebrew/hardcoded locale in migrated files, he/en parity, ICU valid, keys exist
   I18N_FRAGMENTS=<frag> node scripts/i18n-check-keys.mjs <file>
   I18N_FRAGMENTS=<frag> node scripts/i18n-verify-he.mjs <file>   # every original Hebrew chunk is in he.json verbatim
   ```
6. Typecheck: `npx tsc --noEmit -p tsconfig.json` (fast in the cloud container; on the Mac use a scoped tsconfig).

## English copy
American English, glossary in `docs/us-expansion-plan.md` §6 and `docs/i18n-glossary.md` (Client — never Customer; Appointment; Boarding; Trainer; Service dog; Sales tax; Reports). Sentence case for buttons and titles ("New task", "Save changes"). Keep it short — English is usually longer than Hebrew and must fit the same layout. Unsure → write the best literal translation and add `TODO(en-copy)` to the agent report (never inside the message).

## Tools
| Command | What |
|---|---|
| `npm run check:i18n` | CI gate: migrated files clean + he/en key parity + ICU + `t()` keys exist |
| `npm run i18n:extract -- <file>` | Hebrew strings of a file as JSON |
| `npm run codemod:logical-css -- --write <files>` | physical → logical Tailwind (mirrored) |
| `npm run i18n:verify-he -- <files>` | Hebrew in he.json is verbatim vs `origin/main` |
| `npm run i18n:merge -- <fragments>` | merge agent fragments (conflict = same key, different text) |
